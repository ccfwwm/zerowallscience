# 学术 PPT 工作台

ZeroWall 的“学术 PPT”使用一条有序对话时间线完成材料分析、大纲确认、视觉生成、可编辑对象构建和 PPTX 合成。每页先由 `gpt-image-2` 生成包含完整排版层级的 visual master，再通过 Skill 生成 clean plate，并重建 PowerPoint 原生标题、正文、形状、图表、来源、讲稿和受保护科研图片。

## 对话流程

1. 新建文稿后描述演示目标，也可以直接上传论文、图片、扫描 PDF 或 PPTX 模板。
2. 材料解析、大纲、风格建议、页面生成和合成进度都显示在同一时间线中。详细大纲会逐页列出标题、要点、视觉意图和讲述提示，可展开修改并保存后再确认；操作卡固定在触发它的消息之后，后续状态只原地更新。
3. AI 先建议生成详细大纲。首次大纲只有在用户明确点击后创建；确认大纲后，AI 从内置 Skill 风格中推荐一套主方案和三套备选，也可以根据自然语言生成项目级自定义风格，或者分析上传的 PPTX 模板。
4. 确认视觉来源后直接并行生成全部页面、构建可编辑场景并自动合成 PPTX，不再要求确认封面，也没有费用确认阻断或在线 PowerPoint 画布。
5. 完成后显示以主题命名的实际 PPTX 路径。“打开所在目录”只打开文件夹，不再执行额外导出步骤。

左侧文稿列表可独立打开或删除文稿。每份文稿拥有自己的对话、时间线、模型选择、大纲和生成状态；切换文稿不会取消其他文稿正在执行的后台任务，异步结果也不会写入当前打开的另一份文稿。

输入框支持 `/Skill` 和 `@项目对话`。引用内容、材料摘要、当前大纲、页面版本和任务状态会进入当前 PPT 对话上下文；完整材料正文保存在项目受控目录，不写入 WebView 或 SQLite。

## 连续修改

- “修改第 3 页标题和两条要点”等原生文字、表格或图表修改会创建新的不可变页面版本，重建该页 editable scene，并自动更新同一份 PPTX；不调用图片模型。
- 布局、背景或视觉元素变化会通过 Skill 的 `compile-edit` 使用当前页面视觉、`elementUpdates` 和编辑指令，只重新生成目标页面。一次修改多页时创建一个目标页 Run，并发为 `min(受影响页数, 10)`。
- 更换整套大纲、风格、模板或大范围重排会先在时间线中显示变更清单，用户确认一次后执行。
- 每页保留 `generate / edit / restyle / template / rollback` 版本链。回滚会创建一个新版本，不覆盖历史，并自动重新合成 PPTX。

## 可靠流水线

每页使用持久化依赖任务：

```text
compile_prompt -> generate_visual -> build_editable_scene
                                      |
                                      +-> assemble_pptx -> render_editable
                                                           |
                                                           +-> visual_review -> repair_slide (最多两轮)
                                                                              |
                                                                              +-> register_export
```

- 页面之间并行，同一页按依赖顺序执行；页面视觉完成后即可开始该页可编辑对象构建。
- 页面生成和可编辑场景构建的并发上限均为 10。成功步骤按输入哈希复用，不重新生成成功页面。
- EOF、分块解码失败、429、502、503、超时和可重试连接错误最多自动重试三次，并遵守 `Retry-After`。
- 应用退出、切换文稿或进程中断后，SQLite 中的 Run、Job、依赖、attempt 和 lease 用于恢复未完成步骤。
- 自动重试耗尽后，可重试指定页面或全部未成功步骤。失败任务保留原记录，新重试不会破坏成功页面和页面版本。

首次合成后会回渲染全部页面，并由视觉模型检查文字裁切、错位、遮挡、素材失真和与 visual master 的明显偏差。后续轮次只复查失败页，最多进行两轮坐标、字体、裁切和层级修复；仍未通过的页面以警告登记，不阻断可打开的 PPTX。用户可在 PowerPoint 中继续检查并通过对话指定页面修改。

## 材料与安全

- PDF、DOC、DOCX、PPT 和 PPTX 优先提取正文；文本不足的 PDF 使用共享 Python 环境中的 PyMuPDF 渲染页面并进入视觉分析。
- PNG、JPG、JPEG 和扫描 PDF 页面会发送给当前可用的视觉对话模型，不会永久停在 `needs_vision`。
- 受保护科研原图默认作为独立 PowerPoint 图片对象嵌入，不发送给图片模型重绘；只有用户明确要求时才改变该约束。
- API Key 继续保存在系统 Keychain。文稿、时间线、Run 快照和日志均不保存 Key、完整请求载荷或完整 Prompt。
