# ZeroWall Science 7.1.0 论文与图片完整性筛查计划

状态：实施计划，尚未修改检测器、安装新依赖或发布 7.1.0。基线为当前 7.0.5 源码。本文将用户提供的《功能补全总结_给工程师.md》作为待验证需求和回归线索，不把附件中的指控、计数或阈值当作已经独立证实的结论。

## 1. 目标和边界

1. 对输入论文、其 Source Data、Extended Data、Supplementary、未裁剪印迹和独立图片，提供整图、同图局部、跨图局部、跨文件局部比较。每个结果可追溯到文件、页码、面板坐标、方向、匹配证据和检测版本。
2. 补齐 B1–B5 数值审计，覆盖 XLSX、可解析表格和图中数字；数值不可读时明确记录缺口。保留现有正文抽样 WebSearch 核查，不将本版描述为全文文本查重。
3. 7.1.0 默认运行现有哈希/OpenCV/ManuSift 链路及改进的子图匹配。用户选择按需启用 `imagededup` CNN 候选召回。CNN 分数不能单独构成 `high` 证据。
4. 自动输出“异常线索，需人工复核”，不依据图像相似或异常数值直接认定学术不端。同一未裁剪印迹在正文和扩展数据中被合法重复引用也应显示上下文。

## 2. 当前基线与上游融合

当前 `resources/skills/zerowall-image-dup/scripts/vendor/manusift/detectors/image_forensics.py` 的跨图 SIFT 只取前 24 张图片，得到第 15 条发现后立即退出；同图面板最多取 8 块，得到第 12 条发现后退出。`sift_copymove.match_two_arrays` 主要凭 RANSAC 内点判定，尚无变换后重叠区 NCC、墨量和边缘密度复核。`batch_scan.py` 已有跨批次整图/区域扫描和检查点，应保留并接入统一覆盖率。`zerowall_integrity.py` 已支持多输入、`--data`、MinerU 解析结果和任务续跑，但伴随文件不是默认发现，报告没有完整的逐层覆盖率。

指定上游 `yunbolyu/duplicate_image_detection` 固定在提交 `6f1cc50ad9e0097a80b1b7b6c12deff657b21809` 评估。其 `split` 脚本是固定行列均分，适合补充“显式网格候选”，不能直接替代科学图像的自适应面板分割；示例使用 `imagededup` CNN 搜索切图近重复，不能输出重叠坐标或证明图像造假。现有整图 pHash/aHash/dHash 能力不重复移植。根目录 MIT、所带 `imagededup` 代码 Apache-2.0，实施时记录来源、提交、改动范围和许可证；优先通过 PyPI 安装正式包，不复制其旧版子目录。

| 上游能力 | 7.1.0 融合点 | 边界 |
| --- | --- | --- |
| 固定行列切图 | 自适应面板失败时尝试 1×2、2×1、2×2 等显式网格，并记录父图和原图坐标 | 不将网格切片相似直接报 `high`；防止一个真实面板被切成多个虚假命中 |
| `imagededup` 哈希 | 与现有整图哈希对照作回归基线 | 不并列重复执行四套哈希、重复报同一发现 |
| `imagededup` CNN | 按需安装的面板/子图候选召回，支持批量编码、缓存和候选排序 | 无候选时不得称已完成局部复核；相似度不等于物证 |
| 上游评测示例 | 固定正负样本和阈值扫描的离线评测脚手架 | 上游 0.97 阈值只是示例，必须以本地样本校准 |

## 3. 实施阶段

### P0-0 样本与基线

- 保留现有未跟踪文件；记录 Git HEAD、当前 7.0.5 检测输出、Python/Node 版本和耗时。以 `C:\softworks\gpt-tools\问题勘误` 建立只读输入清单：主文、附件、图片、文件 SHA-256、页码/图号和人工核定的正负标签。不要修改原始材料。
- 将 T1–T8 拆成可验证断言，保存预期文件/页码/面板、允许的方向和应显示的数值来源。PubPeer 配图用于定位，真值要回到论文和原始伴随数据核对。补充同一组织图、相邻统计图、空白背景、共享图例、合法重复说明等负样本，评测时不参与阈值调参。
- 附件声称 mTORC2 循环小数 104 处；当前对 XLSX 的一次正则读取为 103 个单元格。实施前按 sheet/坐标/原始单元格文本复核计数，最终以可列举坐标为准。

### P0-1 全局配对、局部配对与续跑

- 在 `image_forensics.py` 删除 24 张候选和发现数提前退出。对所有合格图片建立稳定 ID；图片级可能配对数、实际完成数、排除数分别计数。按块比较，显式配置 `MAX_PAIRS` 作为单次运行预算，保存下一对的游标；相同输入/版本续跑直至覆盖完整。发现全部排序、合并后才截断展示，原始候选计数和证据仍可查。
- 整图层对所有图片执行字节/对象身份及哈希比较；对所有合格跨图图片对执行局部几何检测或明确报告未完成的配对。整图哈希距离不能过滤掉缩放加局部重叠的候选。可按哈希/CNN 线索调整处理顺序，但不能把排序当成完成覆盖。
- 面板层先跑已有轮廓和留白分割，再加入上游显式网格候选与自适应间隙阈值；保留每个子图的原图 bbox、缩放、分割方法、文件和页码。去掉 8 面板/12 发现截断，缩小最低面板尺寸的试验值从 40 px 到 24 px，以误报集校准。建立同图面板、跨图面板和跨文件面板配对队列，显式报告合格、筛过、已几何复核、未复核数量。
- 对 PDF 中绘制的嵌入图、未裁剪印迹、独立 JPG/PNG 保留 xref/原始字节身份；需要时补页渲染图以覆盖矢量或未按嵌入图提取的面板。相同 xref 是强“复用”证据，但报告仍展示图注和可能的合法重用关系。

### P0-2 局部证据与误报控制

- 扩展 `sift_copymove.py`：对 `id`、`flipH`、`flipV`、`rot180` 分别做多尺度 0.7/1.0/1.4× 特征匹配、RANSAC，记录单应/仿射变换、匹配点和原图坐标。按图像复杂度设 keypoint 预算，缓存特征避免重复解码；每个方向须单独计数。
- 几何对齐后仅在有效重叠掩膜计算 NCC/SSIM，记录面积占比、有效像素数、内点数和残差。用局部墨量、边缘密度与纹理信息拒绝白底/黑底、坐标轴、图例和空白条带造成的高 NCC。成像类与统计图类分开校准；图形类需要更强的像素/数据证据。
- `high` 需同时满足定位、足够有效重叠、几何一致与复核阈值；T1 目标 `warp_ncc >= 0.85`，T2 必须显示非 `id` 的方向。阈值由正负样本锁定后再跑盲测，不将单个 SIFT 内点数或 CNN cosine 作为结论。报告提供原图、双侧裁剪、叠图和变换参数。

### P0-3 伴随文件和 B1–B5

- 在 `zerowall_integrity.py` 增加按主文同目录及相邻 `Source Data`、`Extended Data`、`Supplementary` 目录发现附件的入口；显示发现清单、纳入/排除理由，避免误把别篇论文附件合并。PDF、图片、XLSX、CSV/TSV 各走合适解析器；显式 `--data` 保持可用。主文与伴随图一并送入跨文件图片对队列。
- B1 循环小数：在原始 XLSX 值/公式缓存和文本中定位 `(\d{2,4})\1{2,}` 类模式，排除格式显示、ID 和时间戳；输出 sheet、坐标、原始值和聚集程度，单数据集至少 5 处才考虑 `high`。
- B2 数值同一性：将图号/面板、单位、小数文本和数值来源关联，发现跨图长尾小数相同；同源数据或同一归一化基准需降级或解释。仅 OCR 猜测的数字须二次识别或人工核对。
- B3 公式可重算性：抽取声明公式、输入量、单位、测量精度、舍入方式和输出量；用 Decimal/区间运算复算，给出最小可复现精度与差异。没有明确公式或精度时写“未评估”，不能推定错误。
- B4 重复结构：检测组间逐项同值、面板内样本数 `n` 不一致及异常重复精度；保留每个数据点的单元格/图中位置，区分技术重复、生物重复、共享对照和模板占位。
- B5 表格算术：核对行列和、分组人数、总数、百分比与声明 `n`；输出原值、重算值和所用等式。图片表格先由现有 MinerU Precision OCR 获取数字与 bbox，必要时才按需安装本地 OCR 作补充；OCR 没有达到可复核精度时不报算术 `high`。

### P1 按需 CNN 召回与依赖

- 通过同一个 `zerowall-image-dup` Skill 暴露可选的 CNN 模式和依赖检查状态。只在用户启用后安装 `imagededup==0.3.3.post2`、兼容的 `torchvision` 等缺失依赖；同一共享 Python 使用现有在线预览/应用依赖计划、签名清单和用户所选镜像。当前清单含 `torch==2.14.0`、`scikit-learn==1.9.0`，无 `torchvision`；PyPI `torchvision==0.29.0` 声明 `torch==2.14.0`，仍需在托管 Python 3.12.10 Windows x64 中做 dry-run、`pip check` 和导入/推理实测。`imagededup` 的 cp312 Windows x64 wheel SHA-256 为 `f52308cc83162c636a7a3c7a862fe703be34645bb8ec5eca986b2a2f030e82d5`。
- PyPI 包的 torchvision 权重下载应单独提示并缓存，记录模型名、权重版本、实际文件哈希和网络失败原因。首运行失败时默认链路继续运行，CNN 维度标记“未评估”；不得隐式升级已有 torch 或打包大模型进默认安装包。
- CNN 对面板/子图编码并在可比候选中搜索，返回候选 pair ID、cosine、模型版本和 bbox；交给同一方向 SIFT + warp-NCC 验证。实测比较“关闭/开启 CNN”对 T1–T8 召回、误报、内存、权重下载量及时间的增益。若与共享运行时冲突，可保持 7.1.0 默认检测完整并将 CNN 标为不可用，发布门槛仍要求可选路径可安装或明确从 7.1.0 范围移除。

### P0-4 报告与覆盖率

- 在 `findings.json`、Markdown、HTML 首页统一输出至少四维覆盖：图片/面板对（`possible`、`compared`、`verified`、`remaining`、排除原因）、已测方向、OCR 图/表（`done`、`needed`）、伴随文件（发现、已扫、失败）；另列 B1–B5 状态、每个检测器跳过数和 CNN 启用状态。`partial` 与 `incomplete_execution` 分别表示材料/能力缺口和可续跑的未完成工作。
- 首页硬事实示例：`跨图局部：已几何复核 6323 / 16110 对；方向 id/flipH/flipV/rot180；预算剩余 4120 对。伴随文件：发现 3、已扫 3。` 数字必须由检查点统计生成，不能从“步骤 completed/planned”推断配对覆盖。
- 覆盖不足、OCR 失败、附件未提供、依赖不可用、超预算时统一写“未评估（具体原因）”，不得写“未检出问题”。每条 finding 附版本、输入哈希、原始证据、定位、阈值和潜在合理解释。

## 4. 验收矩阵

| 编号 | 原始材料与目标 | 必须输出 |
| --- | --- | --- |
| T1 | WDR6 Fig 2e 与 Fig 7j | 跨图局部复用 `high`，bbox/叠图，`warp_ncc >= 0.85`，覆盖到后段提取图 |
| T2 | eEF2K 垂直翻转的两图 | `high` 且方向为 `flipV` 或等价变换，给出双侧裁剪 |
| T3 | MRG15 Fig 3a | B4a 逐项同值与 B4b 样本数不齐，各自有坐标/来源 |
| T4 | MRG15 Fig 7c | B4c 重复精度异常及具体数值证据 |
| T5 | mTORC2 Fig S8B | B5 分组人数之和与声明总数的重算证据 |
| T6 | mTORC2 Fig 4f/4h/S9g | B2 长尾小数同一性和跨面板来源 |
| T7 | mTORC2 统计 Source Data | B1 循环小数坐标清单，B3 精度/公式复算 |
| T8 | mTORC2 归一化百分比 | B3 两个百分数对应输入及公式复算差异 |

发布门槛：T1–T8 全部达到各自断言；人工标注、与调参集分离的负样本按“独立告警事件”计假阳性率不超过 5%；`high` 的错误报警为阻断项。单篇不超过 250 图的 10 分钟为优化目标，不牺牲完整覆盖；超过时须可续跑并准确标记剩余对数。另测多主文/跨附件、重复文件名、无 OCR、无 CNN、权重下载失败、PDF xref 重用、空白背景、不同页合法复用及预算中断恢复。回归必须在源码与打包后的 Host/Desktop 中均能读取报告和证据。

## 5. 交付顺序与发布

1. 冻结样本标签、记录基线及上游许可；先落覆盖率契约和续跑配对队列，再改局部验证，避免新算法掩盖旧截断。对应 P0-0、P0-1、P0-4。
2. 落方向匹配、warp-NCC、内容门控、自适应/显式网格，跑 T1/T2 与图形类负样本；随后接入附件自动发现和 B1–B5，跑 T3–T8。
3. 加入可选 CNN 模式及在线依赖预览、权重缓存、失败降级；更新 `zerowall-image-dup`、`zerowall-paper-analysis`、`zerowall-paper-compare`、`zerowall-integrity-report` 的使用与覆盖率措辞。保留同一 Skill 入口，不新建独立插件或侧栏。
4. 执行 Python 单测/样本评测、TypeScript 类型和测试、整机及打包冒烟；检查安装包大小、默认无 CNN 路径、共享 Python 依赖及模型缓存隔离。保存 T1–T8、负样本、覆盖率、性能和依赖安装的验收记录。
5. 版本统一升到 7.1.0，生成安装包与更新元数据并核对版本/哈希；先发布七牛云且从公网完整下载校验字节和 SHA-256，再发布 GitHub 代码、tag、Release/资产并回读验证。任一发布门槛失败则不宣布 7.1.0 完成。

已知剩余边界须写入最终报告：极细条带级拼接、强亮度/裁剪后的 loading control 复用、矢量图中重绘元素、非线性局部形变，以及没有原始数值或清晰扫描时的数值无法复核。
