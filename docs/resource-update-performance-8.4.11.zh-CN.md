# 8.4.11 插件与 Skills 更新优化实施计划

## 问题分析

更新链路中的多次文件遍历和复制会放大 Windows 文件系统开销：候选 profile 之外再次创建完整备份、pnpm 再次创建事务候选、逐文件串行校验，以及前台等待候选目录删除。随着安装历史增长，用户可能长时间看不到下载以外的进度。Skills 逐项调用更新还会重复获取 catalog、串行下载和解包；没有解包超时或文件进度时，慢磁盘和损坏归档容易表现为一直等待。

以上是代码路径中的放大因素。构建时的 `runtime-assembly` 处理开发依赖闭包，属于另一条链路；其耗时不能直接作为用户更新的性能数据，也不能用进程有 CPU 活动证明真实更新体验已经通过。

## 实施顺序与范围

1. **减少重复工作。** 插件回滚快照只保存本次受影响包及解析到的依赖实例，保留独立回滚字节；候选 profile 内的 pnpm 使用受 PID/token 认证的已有事务。未请求且完整的已安装依赖复用当前版本，完整性检查保留。
2. **让等待可见、可取消。** 文件复制报告文件计数并检查取消信号，依赖摘要使用有界并发；桌面主进程、preload 和扩展中心传递阶段、当前资源、数量、日志与可取消状态。激活阶段按实际事务能力关闭取消，避免向用户报告已取消但资源已激活。
3. **把收尾移出前台。** 废弃候选目录原子改名到 UUID 清理队列，启动后恢复处理；保留路径和物理目录校验，避免遍历用户导入内容或链接目标。
4. **合并 Skills 批量更新。** 一次读取并验证签名 catalog，有界并行准备归档，解包提供取消和超时，逐项调用 Host 热刷新。版本写入实际 Skill 元数据，避免完成后继续提示同一版本更新。
5. **集成资源并打包。** 桌面版本 8.4.11；Base 0.1.29、扩展中心 0.1.17、MCP 0.2.22。同步 ToolUniverse 和现有科学 Skills，按完整最新共享插件清单装配，核对公开签名 catalog，禁止降级或遗漏。已有同版本归档字节冲突时提升组件版本，不覆盖归档。

## 验证与交付

- 更新回归覆盖选择性快照、独立回滚字节、伪造事务拒绝、复制取消、Skills 批量更新和版本写入；安全及更新合同测试继续执行。
- 使用系统 `C:\Program Files\Python312\python.exe` 验证科学依赖和 Research 测试；测试所需缺失依赖安装到系统解释器的用户目录。产品固定 Python 安装根及签名 bootstrap 合同仍由产品资源配置管理。
- 新 build ID 生成安装器，检查完整插件快照、Skills 实际文件树、签名资源收据、ASAR/runtime 闭包、Host 启动、Electron、更新 smoke、`dsh --version` 和 `zws --version`，记录字节数与 SHA-256。
- 检查结果和未通过项写入 `artifacts/verification/8.4.11`。真实旧用户 profile 的更新耗时、取消和回滚应单独验收；自动测试及构建通过不能替代这项证据。
- 本任务只生成本地产物；公网发布、Git 提交/推送和 Release 创建不在本次打包范围。
