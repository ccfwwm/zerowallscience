# 上下文预算与 Skills / MCP 按需加载（8.4.16）

## 目标与消耗口径

按请求区分未缓存输入、缓存读取、缓存写入和输出。缓存读取仍占模型上下文；多次响应的累计 token 不能当成某一次请求的上下文长度。推理强度主要影响推理输出和费用，不能用来解释重复发送的大量 Skill 摘要与工具定义。

本次会话基线为 6 次响应合计 632,575 token：缓存读取 375,728、未缓存输入 248,647、输出 8,200；单次最高 135,337。267 条 Skill 摘要约 83k 字符、298 个工具定义约 169k 字符、10 个工具结果约 72.5k 字符。字符数只用于定位来源，不能直接当作 token 数。日志未出现压缩事件也不能单独证明压缩失效，因为压力检查发生在下一次请求前。

先减少固定输入，再控制历史增长。预算是模型输入的软上限，实际阈值还受模型窗口、输出预留和压缩可选范围限制；它不会扩大模型本身的窗口。

## 已实施的工作

1. **系统提示词**：保留产品身份、共享 Python、权限、凭据与科学结果真实性约束；移除 `harness:source` 的全量源码/API 说明。领域指导放在按需读取的 Skill 中，静态提示只说明如何发现能力。
2. **Skills 发现**：常驻 `skill_search`，可先浏览分类，再按任务检索，单次最多返回五条摘要。普通请求最多携带三条相关短摘要；完整正文仍通过原生 `skill` 工具或显式 `/name` 载入。未检索的正文不进入请求。
3. **Skills 重复与旧历史**：同名 Skill 继续遵守 DSH 的来源优先级，自定义版本优先于内置版本。审计精确正文摘要，避免按名称相似度误删用户内容；本次 281 个 Skill 的审计没有发现正文完全相同的副本。旧会话的全量目录通过追加替代事件精简，原始事件不删除。语义近似的 Skill 仍保留，后续可根据实际检索质量合并。
4. **MCP 按需连接**：启动仅准备连接记录与本地工具索引；搜索元数据不会启动全部 Server。需要的连接经 `mcp_connect` 或 Host 领域工作流建立，实际调用仍读取实时 Schema 并走原权限、凭据和运行时检查。
5. **MCP 与缓存**：当前 Agent 只看到选中连接的原始工具，其他 Agent 不因某个连接已经启动而接收其全部定义。选中集合在 Agent 内保持，避免每一步反复增删；工具索引跨重启保存，连接参数变化后失效。索引只用于发现，不能作为执行契约。新增工具定义仍可能使服务端提示缓存失效；保持相同工具集也不保证服务端命中。
6. **上下文预算**：环境设置默认 300k，滑块支持 32k–2,000k，按 4k 调整。有效预算取用户预算与模型窗口的较小值；压力阈值取有效预算的 90% 与“窗口减输出预留及 16k 余量”的较小值。先精简工具结果，再摘要较早历史，保留最新消息与完整工具调用/结果配对。
7. **实际压缩服务**：从当前 Agent 预设取得 `compaction`，兼容存在全局服务的组合；不把会话隔离服务设为全局激活依赖。使用 DSH 的追加式压缩事务，保留原始日志与可恢复的事件链。
8. **推理档位**：支持 High 且未显式选择档位时默认 High；滑块只列出当前模型真实支持的档位，保留用户选择的模型、协议、输出参数及其他推理档位。
9. **Research 项目流程退役**：Research 查看器插件、项目/Study 工作台、`research_study` 工具、注册与 Study 管理 RPC 已从默认安装包移除。远程科学分析仍通过 MCP 工作流运行；不自动创建或注册远程 R 项目，需要项目 ID 的操作使用用户已有项目。已有数据库、会话日志和任务历史保留，不再自动创建 Study、计划草稿或 Gate。
10. **插件更新**：确保新安装器携带当前依赖事务、物理化与解析脚本。更新通过候选依赖解析、受影响路径提交、Host 健康检查及失败恢复完成；验证清理候选目录后仍能独立导入 `plugin-base` 的 `lucide-react` 依赖。

## 发现、执行与缓存的实际路径

Skills 的主入口是小型分类检索工具，不额外生成一个包含全部正文的“总 Skill”。模型可先调用不带查询的 `skill_search` 查看分类，再按任务或分类检索，最后用精确名称调用原生 `skill`。分类和搜索只读摘要；来源优先级、禁用选择、自定义覆盖与显式 `/name` 都保留。相似名称不视为重复；只有确认正文及配套资源等价后才适合人工合并，避免误删同名不同用途的技能。

MCP 的本地索引只存工具名称、截短描述、Schema 摘要和连接配置摘要。首次没有索引时可通过连接名称查找，或用不带 server 的 `mcp_connect` 浏览连接；尚未连接过的服务无法凭空提供完整工具语义。连接成功后更新索引，下一次启动可检索这些元数据。实际执行始终连接服务并使用实时 Schema。凭据原值不写入索引；配置变化使旧索引失效。

新增工具会改变请求前缀，可能降低该次提供方的缓存命中。当前方案通过保留当前 Agent 已选择的工具集合减少来回切换；不同 Agent 互不注入工具。不承诺动态加载与固定工具集具有相同缓存命中率，验收同时观察总输入、未缓存输入、缓存读取和输出，不能只看缓存百分比。

预算例子：模型窗口 1M、用户预算 300k、输出预留 32k 时，约 270k 触发压力处理；模型窗口 128k 时，即使滑块设置 300k，阈值仍受 `128k - 输出预留 - 16k` 约束。先做无需模型的工具结果精简，再选择较早的完整调用区间生成摘要。原始日志不删，最新消息和调用配对保留。预算数值由环境配置持久保存，推理档位由模型能力决定，两者独立。

## 边界与后续诊断

- 模型窗口元数据缺失、输出预留超过窗口或没有可安全摘要的范围时，记录明确原因；不擅自更换模型或缩小用户输出设置。
- 压缩失败记录诊断，原始历史保持；模型原有的压力与溢出恢复继续工作。预算不是严格的逐 token 请求拦截器，大条新输入仍可能在下一轮计量前超过预算。
- 摘要会产生一次额外模型请求；固定系统提示和当前工具定义不能靠历史摘要消除。长会话不断选择新 MCP 时，工具定义仍可能增长，可通过新会话缩小所需能力集合。
- `cache-diagnostics` 记录系统提示、工具 Schema、Skills、动态上下文、路由与历史前缀的摘要及提供方 usage。只记录诊断元数据，不落完整提示、正文或凭据。应分别评估首次请求体积、后续未缓存输入与提供方真实缓存命中率。
- 不自动删除自定义 Skills、MCP 配置或旧研究数据库，不在启动检查中自动安装或更新插件、Skills、MCP。

执行仓库类型检查、插件/存储/桌面测试、合同、安全和更新测试。Windows 新 build ID 必须核对完整插件快照、ASAR/离线闭包、Host、Electron、命令版本、安装器字节数与 SHA-256。测试日志与最终收据存放在 `artifacts/verification/8.4.16`。

完成验收后按已授权流程先发布并公开验证七牛，再推送源码/tag 与 GitHub Release；从 GitHub 下载安装器，与本地及七牛的 SHA-256 比较。精确产物、build ID、公开 URL 与跳过项目写入本次交付收据。
