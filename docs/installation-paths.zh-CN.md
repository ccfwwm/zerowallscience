# 安装目录、活动 profile 与离线供给

## 目录责任

| 位置 | 用途 | 运行期规则 |
| --- | --- | --- |
| `%LOCALAPPDATA%/Programs/ZeroWallScience` | 当前用户的应用二进制、共享 DSH 核心、命令和默认资源 | 安装器管理；不是用户项目或插件更新根 |
| `<userData>/harness/profiles/web/node_modules/<插件名>` | 活动插件及其文档、客户端和服务端入口 | Host、CLI 与插件更新使用同一 profile |
| `<profile>/node_modules/.zerowall-dependencies` | 已物化插件的非核心共享依赖 | 由 profile 事务维护，不依赖安装器离线目录 |
| `<安装目录>/resources/offline-profile` | 安装器签名供给，内含 ASAR 及必须在磁盘上的文件 | 首次安装、版本升级或尚未清理时的本地修复使用；不是运行解析回退 |
| `%APPDATA%/zerowall-science` 与历史 `zerowall-science-3` | 旧安装的 userData 根 | 首次启动仅恢复必要用户数据；成功且工作台就绪后异步清理明确运行时和缓存，原对话、凭据和配置保留 |
| `%LOCALAPPDATA%/zerowall-science` | 新安装解析得到的 userData 根 | 与二进制目录区分，允许显式覆盖；恢复完成收据使后续启动直接使用当前数据 |

`C:/...` 与 `C:\...` 的分隔符差异不代表不同版本；`Local/Programs` 与 `Roaming` 才是职责不同的根。路径必须通过 `join`、`resolve` 与 profile/runtime 锚点构造，禁止重复拼接安装根，也不能通过遍历同级其他软件来寻找插件。

## 安装与启动顺序

1. 打包从完整共享插件清单读取实际版本和摘要，核对线上已签名版本，拒绝降级、缺项和同版本不同字节。复用不变归档，生成新桌面 build ID。
2. 安装器携带已验证插件的完整离线可运行闭包。默认插件首次安装和桌面升级不需要联网下载；网络只用于用户主动资源更新、只读目录检查及独立的 Python 后台维护等功能。
3. Windows 安装包未显式指定数据根时，在 Host 与凭据读取者启动前，按白名单从旧 Roaming 根补齐聊天、附件、工作区索引、账户和环境变量凭据、用户 patch、SSH 配置及自定义 Skill。主旧根优先于历史 `-3` 根；当前数据和选择优先，同账号凭据成组恢复，避免不同账户混用。不同目录的 Windows 加密密钥通过当前用户 DPAPI 在内存中解开，凭据重新加密后写入新根；不覆盖 Local State，不输出密钥或明文。先前错误复制的密文也重新加密，解密失败不再删除条目。配置改动原子写入并备份；同路径不同长度的聊天文件保留双方。只有全部步骤成功才写 `.migration/essential-user-data-v1/completed.json`，后续启动只检查收据，不再扫描旧数据。失败保留源数据、备份并提示下次启动重试。程序依赖、Python、缓存及 CLI profile 不迁移。
4. 必要数据恢复成功且 Windows 安装包的 Host 与工作台均就绪 5 秒后，才异步删除旧 Roaming 根中的明确运行文件：Chromium 缓存、旧 Python 目录、旧插件依赖、UUID 安装候选、下载缓存和待清理候选。只浅读候选目录名，不预先盘点文件树。逐项删除失败仅记录错误码并继续，下次健康启动重试。旧根本身、对话及附件、账号/模型/环境变量配置、用户设置、导入内容和插件选择不删除；固定 Python 根、当前数据根、显式自定义数据根及链接重定向目录受保护。源码开发模式不恢复或清理旧用户目录。
5. 启动优先验证活动 profile 的签名物化收据、物理入口和依赖。健康且匹配当前安装版本时不读取离线供给，不在后台再次触发离线修复。
6. 初次安装、缺失/损坏或新桌面需要同步托管资源时，才使用当前安装包供给，经现有事务与 Host 健康流程处理。独立升级、固定版本、禁用和移除选择继续按既有合同保留。
7. Host 与工作台均就绪后，在 profile 写锁内执行独立完整校验，检查 profile 中的链接未指向待清理供给。
8. 仅对当前用户标准 `%LOCALAPPDATA%/Programs/ZeroWallScience/resources/offline-profile` 实体目录执行精确清理。开发、共享、自定义或经过链接重定向的安装跳过；不枚举其他软件目录。清理无网络、无 Host 重启；失败非阻塞，下次健康启动重试。

## 保留边界与验收

- 不删除旧 userData 根及其用户数据、固定 Python 安装、用户导入内容、签名密钥或未知历史目录。只有上文列出的旧运行时/缓存路径参与后台删除；当前 profile 的 `node_modules` 不在此清理范围。
- 历史 `resources/offline` 可能为高版本/固定插件提供溯源，不能仅凭“旧”而删除；它也不得成为 Host 的解析回退。
- 已有活动 profile 的 disposable candidate 清理由既有 UUID/所有权合同处理；旧根只识别严格 UUID 命名的 `zerowall-pnpm-*` 安装候选，不扩展成通配符或全盘清理。
- 回归覆盖供给删除后正常/完整检查、独立插件升级、DSH 变化、缺入口、桌面升级、共享/自定义安装、junction、防引用删除、错误降级与重复清理。
- `node --test desktop/e2e/legacy-startup.test.mjs` 使用真实包和默认 LocalAppData 解析路径，通过启动前调试器将 Windows known folder 绑定到临时目录，不设置会绕过恢复的自定义数据根；验收不同加密密钥、旧密文修复、聊天可见、完成收据、健康重启和就绪后异步删除。真实用户目录不参与写入。
- 打包前核对当前源码和并行任务状态，记录源码摘要；其他修改进程已经确认完成时直接按当前源码打包。最终验收安装器、ASAR/闭包、版本输出、集成快照、大小、SHA-256 与新 build ID；测试通过不等于真实安装/公网发布已完成。
