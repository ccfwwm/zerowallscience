# 安装目录、活动 profile 与离线供给

## 目录责任

| 位置 | 用途 | 运行期规则 |
| --- | --- | --- |
| `%LOCALAPPDATA%/Programs/ZeroWallScience` | 当前用户的应用二进制、共享 DSH 核心、命令和默认资源 | 安装器管理；不是用户项目或插件更新根 |
| `<userData>/harness/profiles/web/node_modules/<插件名>` | 活动插件及其文档、客户端和服务端入口 | Host、CLI 与插件更新使用同一 profile |
| `<profile>/node_modules/.zerowall-dependencies` | 已物化插件的非核心共享依赖 | 由 profile 事务维护，不依赖安装器离线目录 |
| `<安装目录>/resources/offline-profile` | 安装器签名供给，内含 ASAR 及必须在磁盘上的文件 | 首次安装、版本升级或尚未清理时的本地修复使用；不是运行解析回退 |
| `%APPDATA%/zerowall-science` | 已有安装的历史 userData 根 | 原地复用，不为目录整齐而迁移或删除 |
| 新安装解析得到的 LocalAppData userData 根 | 新数据根，遵守 `user-data-location.ts` | 与二进制目录区分，允许明确指定数据根 |

`C:/...` 与 `C:\...` 的分隔符差异不代表不同版本；`Local/Programs` 与 `Roaming` 才是职责不同的根。路径必须通过 `join`、`resolve` 与 profile/runtime 锚点构造，禁止重复拼接安装根，也不能通过遍历同级其他软件来寻找插件。

## 安装与启动顺序

1. 打包从完整共享插件清单读取实际版本和摘要，核对线上已签名版本，拒绝降级、缺项和同版本不同字节。复用不变归档，生成新桌面 build ID。
2. 安装器携带已验证插件的完整离线可运行闭包。默认插件首次安装和桌面升级不需要联网下载；网络只用于用户主动资源更新、只读目录检查及独立的 Python 后台维护等功能。
3. 启动优先验证活动 profile 的签名物化收据、物理入口和依赖。健康且匹配当前安装版本时不读取离线供给，不在后台再次触发离线修复。
4. 初次安装、缺失/损坏或新桌面需要同步托管资源时，才使用当前安装包供给，经现有事务与 Host 健康流程处理。独立升级、固定版本、禁用和移除选择继续按既有合同保留。
5. Host 与工作台均就绪后，在 profile 写锁内执行独立完整校验，检查 profile 中的链接未指向待清理供给。
6. 仅对当前用户标准 `%LOCALAPPDATA%/Programs/ZeroWallScience/resources/offline-profile` 实体目录执行精确清理。开发、共享、自定义或经过链接重定向的安装跳过；不枚举其他软件目录。
7. 清理无网络、无 Host 重启。失败非阻塞，下次健康启动重试；部分清理后健康 profile 仍独立启动。清理后若活动插件损坏，明确提示重新运行同版或新版安装器恢复本地供给。

## 保留边界与验收

- 不清空或搬迁用户数据，不删除 `node_modules`、固定 Python 安装、用户导入内容、签名密钥或未知历史目录。
- 历史 `resources/offline` 可能为高版本/固定插件提供溯源，不能仅凭“旧”而删除；它也不得成为 Host 的解析回退。
- 已有 disposable candidate 清理由既有 UUID/所有权合同处理；本次不扩展成通配符或全盘垃圾清理器。
- 回归覆盖供给删除后正常/完整检查、独立插件升级、DSH 变化、缺入口、桌面升级、共享/自定义安装、junction、防引用删除、错误降级与重复清理。
- 打包前核对当前源码和并行任务状态，记录源码摘要；其他修改进程已经确认完成时直接按当前源码打包。最终验收安装器、ASAR/闭包、版本输出、集成快照、大小、SHA-256 与新 build ID；测试通过不等于真实安装/公网发布已完成。
