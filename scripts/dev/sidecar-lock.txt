# Sidecar / bundled-asset integrity lockfile
#
# Every artifact that scripts/dev/fetch-*.sh downloads off the network is pinned
# here by SHA-256. The fetch scripts verify the bytes they downloaded against
# these pins and ABORT the build on mismatch, so a compromised mirror, a
# re-tagged release, or a truncated download can never reach a shipped
# installer. See scripts/dev/verify-digest.sh for the checker.
#
# ---------------------------------------------------------------------------
# FORMAT
# ---------------------------------------------------------------------------
# One pin per line, four whitespace-separated fields:
#
#   <artifact> <version> <target> <sha256>
#
#   artifact  logical name used by the fetch script (opencode, uv,
#             agent-browser, ai4s-skills, anthropic-skills, goal-plugin).
#   version   the exact version or commit the script pins. Encoding it here
#             means bumping a version WITHOUT adding its pin fails the lookup
#             loudly instead of silently skipping verification.
#   target    Rust target triple the asset is for, or `any` for a
#             target-independent artifact (source archives, npm tarballs).
#   sha256    lowercase hex SHA-256 of the downloaded file, exactly as it
#             arrives on disk (the archive/binary itself, not its contents).
#
# Blank lines and `#` comments are ignored.
#
# ---------------------------------------------------------------------------
# HOW TO ADD OR BUMP A PIN
# ---------------------------------------------------------------------------
# Never hand-write or guess a digest, and never "fix" a failing build by
# pasting in whatever the file currently hashes to. That turns verification
# back off. A digest is only legitimate from one of two sources:
#
#   1. PREFERRED - a checksum the upstream project publishes for that exact
#      release. For GitHub releases, `digest` on each asset in the release API
#      is computed by GitHub and is the authoritative value:
#
#        curl -sSL https://api.github.com/repos/<owner>/<repo>/releases/tags/<tag> \
#          | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>\
#            JSON.parse(s).assets.forEach(a=>console.log(a.digest,a.name)))"
#
#      Some projects also ship a sidecar checksum file (uv publishes
#      `<asset>.sha256`); npm publishes `dist.integrity` in the packument.
#      Cross-check against it when available.
#
#   2. FALLBACK - compute it from a file you actually downloaded, when upstream
#      publishes no checksum (GitHub source tarballs, for example - the archive
#      `ETag` is NOT a content hash). Download it and run:
#
#        bash scripts/dev/verify-digest.sh --print <file>
#
#      This pins "the bytes that were served when the pin was made". It detects
#      later tampering and transport corruption; it is not a statement about
#      upstream's intent, so review what you downloaded before pinning it.
#
# When bumping a version: change the version in the fetch script (or its
# environment default), then add the new pin rows here and delete the old ones.
# Keep every target the script supports pinned - an unpinned target aborts.
#
# ---------------------------------------------------------------------------
# PINS
# ---------------------------------------------------------------------------
