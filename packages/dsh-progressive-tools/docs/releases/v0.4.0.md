# v0.4.0 — Runtime compatibility and maintenance documentation

This release adapts progressive discovery to host runtime `0.1.5-rc.1`.
Earlier host baselines are no longer supported by this version. Core peers
are pinned to the tested prerelease; later prereleases need separate validation.

## Changes

- Migrate invocation IDs to `ToolCallId` and session access to `snapshotEvents()`.
- Restore current PTC discovery logs and historical nested logs retained as ignorable events.
- Update asynchronous agent initialization and session projection setup in integration tests.
- Assert the real leading system message and serialized tool definitions across requests.
- Add PTC/both-mode regressions for both SDK languages, direct-call denial,
  argument validation, and discovery restoration after plugin reload.
- Align the existing validator dependency and test-time peer graph.
- Add onboarding, migration, troubleshooting, test scope, coding workflow,
  release/rollback instructions, roadmap, and contribution templates.

The `0.3.0` discovery capabilities remain: family-wide discovery, catalog
browsing, optional status grants, multilingual lexical matching, and compact
rendered discovery increments with cumulative recovery metadata.

## Validation

- 46 tests pass across five suites.
- Type checking, lint, build, and package validation pass.
- No peer dependency conflicts in the release validation environment.

PTC tests use the real host dispatch bridge with a binding runtime fixture;
they do not run language interpreters. No live provider cache, cost, or task
success benchmark is claimed.

## Upgrade

Use a host profile on `0.1.5-rc.1`, install this plugin at tag `v0.4.0`, inspect
the profile config dump, and verify a fresh session before testing resume.
Options retain their names and defaults. Back up existing sessions: host
storage migration is separate from plugin discovery replay.

See [migration](../migration.md), [getting started](../getting-started.md),
and [testing](../testing.md). The release includes a built package tarball
and SHA-256 checksum alongside the source archives. This GitHub Release does
not publish the package to an npm registry.
